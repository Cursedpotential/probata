### Flags

- **Step 5 — Direct-landing path violates Rules 12, 19, 22**: The `read_xml` template and repository extension land rows directly into a raw table via `duckdb.query()`, bypassing `PersistRawGeneration`. The Q1=C ruling and Rule 19 require the ELT activity to emit `RawRecordEnvelope` objects that flow through the same persist path as every Go parser. Step 5 must be restructured: the DuckDB template produces split rows; the activity wraps each into a `RawRecordEnvelope` with a `Locator` (byte-range for the record); envelopes flow through `PersistRawGeneration`.

- **Step 5 — Byte offsets mandated despite Rule 14**: Step 5 states the template must "Include `byte_offset` and `byte_length`." Rule 14 explicitly says "for `read_xml` templates, byte offsets are NOT required (Q1=C slow lane: re-parse at promotion)." Remove the byte-offset requirement from the `read_xml` template; the envelope's `Locator` may carry a range, but the template must not be required to compute byte offsets.

- **Step 5 — Missing four-gate enforcement (Rule 12)**: The template description omits `TRY_CAST` into reject rows, count reconciliation, and row digest. Rule 12 requires the same four gates as Go parsers: template output schema, `RawRecordEnvelope`, raw-table constraints, count reconciliation + row digest.

- **Step 6 — `Select(format)` still cannot return "ELT" (Rule 21)**: Adding `SelectRouting` does not satisfy the rule that `Select(format)` must be able to return "ELT." Either `Select` must be modified to return a routing decision (breaking change, but rule-compliant), or `SelectRouting` must be explicitly documented as the canonical replacement for `Select` in routing contexts, with `Select` callers updated.

- **Step 7 — Comparison report not persisted (Rule 10)**: The field/count comparison must be persisted in project documentation (e.g., a findings file under `docs/`), not just produced as terminal output.

- **Step 5 — Migration 0076 depends on 0073/0075 sequencing (Open Items #5)**: Migrations 0073 and 0075 must land before `StoredBytes` removal compiles. The `read_xml` template and its landing table target the post-0075 schema. Step 5 does not acknowledge this dependency; migration 0076 will fail if 0073/0075 have not yet been applied.

### Question-gate residue

1. **Q2 — Router tie-break policy**: When both DuckDB ELT and a Go parser claim a format signature, which dispatches? `SelectRouting` needs an owner ruling on tie-breaking. Affects Step 6.
2. **ELT fallback path — automatic vs HITL gate**: Should the workflow fall back from ELT to parser automatically on logged failure, or gate on HITL review? Affects the `Select` → `SelectRouting` → workflow branch. Blocked on owner ruling.
3. **Landing table — `raw.raw_sms` vs new `raw.raw_xml_sms`**: Which table does the `read_xml` template target? Affects Step 5 migration and repository INSERT SQL. If envelopes flow through `PersistRawGeneration`, this question may resolve to "reuse `raw.raw_sms`" — but the owner must confirm.
4. **DuckDB `read_xml` availability**: Whether pg_duckdb supports `read_xml` with the `xml` extension on the deployed instance. The uncommitted `duckdb.allow_community_extensions` persistence must be in effect. This is a factual unknown that could block Step 5 entirely.
5. **Migration dependency (0073/0075)**: The `read_xml` template and its landing table depend on the post-0075 schema (raw locator-only, no `stored_bytes`). These migrations do not yet exist. Step 5 cannot land until they do.

### Verdict

**REVISE** — Five fixes required before this package can proceed:

1. **Step 5 must route through `PersistRawGeneration` (Rules 12, 19, 22)**: Restructure the `read_xml` flow so DuckDB produces split rows → activity wraps each into a `parser.RawRecordEnvelope` with a byte-range `Locator` → envelopes flow through `PersistRawGeneration`. Remove the direct `duckdb.query()` INSERT path for `read_xml`. Add the four gates: `TRY_CAST` into reject rows, count reconciliation, row digest, and raw-table constraints.

2. **Step 5 must remove the byte-offset mandate for `read_xml` (Rule 14)**: The template must NOT require `byte_offset`/`byte_length`. The envelope `Locator` may carry a range, but `read_xml` operates in the slow lane (re-parse at promotion); byte offsets are optional, not mandatory.

3. **Step 6 must make `Select(format)` capable of returning "ELT" (Rule 21)**: Either modify `Select`'s return type to a `RoutingDecision`, or document `SelectRouting` as the canonical replacement and update all `Select` callers. A separate `SelectRouting` alongside an unchanged `Select` leaves `Select` unable to return ELT, violating the rule.

4. **Step 7 must persist the comparison report in project documentation (Rule 10)**: Write the field/count comparison findings to a durable file (e.g., `docs/read_xml-vs-sbv-comparison-YYYYMMDD.md`), not just terminal output.

5. **Step 5 must acknowledge the migration-0073/0075 dependency and sequence after them (Open Items #5)**: Add a pre-condition that migrations 0073 and 0075 must land before migration 0076 and before the `read_xml` template can target the post-0075 schema. Do not create migration 0076 until 0073/0075 exist.
